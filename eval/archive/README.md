# 评测结果归档

这里存放**已被后续基线取代的评测产物**，纯粹为了保留历史可追溯性——它们记录的是
已经不存在的数据集/数据规模下的运行结果，**无法重新生成**，所以不删除，只移出主目录。

## 为什么会有这些文件

评测结果 CSV 是每跑一次 `python -m eval.run_ragas_eval` 就产出一份，开发期间会快速堆积。
留在 `eval/` 根下会让人分不清哪份是当前基线、哪份是中间调试留下的。

## 归档的是什么

按时间分两批：

**2026-09-19（旧 115 单数据 + 旧 33/63 条评测集）**
当时的开发是"跑一次 → 看一眼 → 调召回阈值 → 再跑"的节奏，所以留下大量中间产物：

- `*_110554 / 110708 / 110856 / 111550 / 113259` —— 1~9 条的冒烟
- `*_114427 / 115616 / 151716 / 162156` —— 通往 33 条基线的若干次重跑
- `*_150330` —— 5 条冒烟

**2026-09-21**
- `jev_judge_20260921_093106.csv` —— Jev 裁判接入时的冒烟（19 行）

## 判据

归档的标准是「**既没有被任何报告/文档引用，也不是某个阶段的完整基线**」——
冒烟（十几条以内）和中间迭代一律归档，被引用的完整运行留在原位。
